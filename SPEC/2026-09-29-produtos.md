# Módulo de Produtos (2026-09-29)

## O quê e por quê

A barbearia "Trim" não vende apenas serviços (cortes e barbas), mas também produtos físicos (pomadas, óleos de barba, shampoos, pentes). Este módulo gerencia o **Catálogo de Produtos** e o **Controle de Estoque**.

### Decisões técnicas
- A gestão de estoque será feita de forma centralizada (apenas a barbearia tem o estoque).
- Não haverá controle de lote ou validade nesta primeira versão (para manter a complexidade gerenciável). O controle será simples: Quantidade X no estoque.
- Quando uma venda é realizada (módulo futuro), o estoque deve ser decrementado automaticamente.
- Apenas Administradores podem adicionar produtos ou alterar o saldo do estoque.

## Entidades

### Product (Produto Físico)
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| name | string | unique, not null, max 150 chars |
| description | text | nullable |
| sku | string | unique, nullable (Código de Barras ou código interno) |
| price | decimal | not null, maior ou igual a 0.00 |
| cost_price | decimal | nullable, maior ou igual a 0.00 (custo de compra para calcular lucro depois) |
| stock_quantity | integer | not null, default 0 (quantidade atual no estoque) |
| is_active | boolean | default true (soft delete) |
| image_url | string | nullable (URL da foto do produto) |
| created_at | datetime | auto-gerado |
| updated_at | datetime | auto-atualizado |

### InventoryMovement (Histórico de Movimentação de Estoque)
Para garantir auditoria, não apenas mudamos o `stock_quantity`, mas registramos quem adicionou/removeu e o motivo.
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| product_id | UUID | FK (products.id), not null |
| user_id | UUID | FK (users.id), not null (Quem registrou a movimentação) |
| quantity | integer | not null (Pode ser positivo (entrada) ou negativo (saída/venda/perda)) |
| movement_type | enum | `SALE` (Venda), `RESTOCK` (Reposição), `LOSS` (Perda/Avaria), `ADJUSTMENT` (Ajuste manual) |
| notes | text | nullable |
| created_at | datetime | auto-gerado |

## Endpoints da API

### Públicos (Clientes)
| Método | Rota | Descrição |
|--------|------|-----------|
| GET | `/api/products` | Lista os produtos ativos e em estoque (vitrine virtual) |
| GET | `/api/products/{id}` | Detalhes de um produto específico |

### Autenticados (Admin)
| Método | Rota | Descrição |
|--------|------|-----------|
| POST | `/api/products` | Cadastra um novo produto (inicia com estoque 0) |
| PUT | `/api/products/{id}` | Edita dados básicos (nome, preço, foto) |
| DELETE| `/api/products/{id}` | Desativa um produto (soft delete) |
| POST | `/api/products/{id}/inventory` | Registra uma movimentação de estoque (entrada ou saída) e atualiza o saldo do produto. |
| GET | `/api/products/{id}/inventory` | Retorna o histórico de movimentações daquele produto. |

---

## Regras de negócio

1. **Estoque Negativo:** Não é permitido registrar uma saída (`LOSS`, `SALE`) que deixe o `stock_quantity` negativo. A API deve rejeitar a movimentação.
2. **Atomicidade:** Toda alteração no `stock_quantity` da tabela `products` DEVE ser acompanhada da inserção de um registro em `InventoryMovement` na mesma transação de banco de dados.
3. **Vitrine:** O endpoint público de listagem só deve exibir produtos com `is_active = True` e, por padrão, onde `stock_quantity > 0` (pode ter um filtro opcional `show_out_of_stock=true`).
4. **Custo Oculto:** O campo `cost_price` (preço de custo) nunca deve ser retornado nos endpoints públicos de listagem ou detalhamento, pois é dado sensível da barbearia.

---

## Critérios de aceitação

- [ ] Criação e edição de produtos restritos apenas para administradores.
- [ ] Endpoint público omite `cost_price` e mostra apenas produtos ativos.
- [ ] Endpoint de inventário (movimentação) exige Admin, aceita valores positivos (RESTOCK) ou negativos (LOSS) e atualiza o `stock_quantity` do produto.
- [ ] O banco rejeita ou a API valida tentativas de baixar o estoque abaixo de zero.
- [ ] Admin consegue ver a trilha de auditoria (histórico) das entradas e saídas de cada pomada/óleo.

## Fora do escopo

- Venda direta online e entrega (carrinho de e-commerce e correios). Os produtos serão comprados e retirados na barbearia (Checkout PDV no balcão).
- Alertas automáticos de "Estoque Baixo" por e-mail (isso ficará para o módulo de notificações).
