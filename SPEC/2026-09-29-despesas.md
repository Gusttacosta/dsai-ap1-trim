# Módulo de Controle de Despesas (2026-09-29)

## O quê e por quê

Complementando o módulo financeiro, precisamos de uma forma de o dono da barbearia registrar as saídas de caixa (aluguel, conta de luz, salários base, compra de estoque de produtos, água, marketing).
Isso permitirá, no módulo de Relatórios (Dashboard), calcular o **Lucro Líquido** (Receita Total - Comissões Pagas - Despesas).

### Decisões técnicas
- O módulo terá um CRUD simples de `Expense` (Despesa).
- Pode ser uma despesa recorrente (todo dia 5) ou avulsa (conserto de um espelho quebrado).
- Não faremos agendamento automático de despesas no banco nesta versão. O foco é registrar a despesa quando ela for paga para ter a visão de fluxo de caixa realizado (Regime de Caixa e não de Competência).

---

## Entidades

### ExpenseCategory (Categoria de Despesa)
Tabela simples para organizar os gastos, podendo ter defaults preenchidos (Infraestrutura, Folha de Pagamento, Marketing).
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| name | string | unique, not null (ex: "Contas Fixas") |
| created_at | datetime | auto-gerado |

### Expense (Registro da Despesa)
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| category_id | UUID | FK (expense_categories.id), nullable (pode ser sem categoria) |
| description | string | not null (ex: "Conta de Luz - Janeiro") |
| amount | decimal | not null, maior que 0 |
| payment_date | date | not null (Data em que o dinheiro saiu do caixa) |
| is_recurring | boolean | default false (Indicativo visual de que essa conta se repete, para facilitar relatórios) |
| created_at | datetime | auto-gerado |
| updated_at | datetime | auto-atualizado |

## Endpoints da API

### Autenticados (Apenas Admin)
| Método | Rota | Descrição |
|--------|------|-----------|
| GET | `/api/expenses/categories` | Lista todas as categorias cadastradas. |
| POST | `/api/expenses/categories` | Cria uma nova categoria. |
| GET | `/api/expenses` | Lista as despesas (com filtros de data de pagamento `start_date` e `end_date`). |
| POST | `/api/expenses` | Registra uma nova despesa paga. |
| PUT | `/api/expenses/{id}` | Edita os dados de uma despesa (valor, descrição, data). |
| DELETE| `/api/expenses/{id}` | Remove permanentemente um registro de despesa (lançamento incorreto). |

---

## Regras de negócio

1. **Acesso Exclusivo:** Diferente das comissões ou da vitrine, apenas contas com role `ADMIN` (o dono) podem interagir com as rotas de despesa. Barbeiros e Clientes não têm visão ou permissão neste módulo.
2. **Exclusão Física (Hard Delete):** Ao contrário dos serviços e produtos (que têm `is_active` por causa do histórico), um lançamento errado de despesa pode ser fisicamente deletado do banco, pois não possui tabelas filhas complexas atreladas a ela.
3. **Data de Pagamento (`payment_date`):** É o campo crucial para cruzar com a tabela de `Transaction` (Receitas) e gerar o relatório do mês. 

---

## Critérios de aceitação

- [ ] Bloqueio rígido na rota, permitindo apenas `ADMIN`.
- [ ] Admin consegue criar categorias de despesa (para não misturar aluguel com compra de cerveja para a barbearia).
- [ ] Admin consegue registrar, editar e deletar uma despesa.
- [ ] Endpoint de listagem de despesas suporta filtros de período (mês/ano) para facilitar o cálculo do fechamento financeiro.

---

## Fora do escopo

- Gestão de "Contas a Pagar" (despesas futuras vencendo). O módulo funcionará apenas como registro do que *já foi pago* para conciliação do lucro real.
- Repetição automática (Cron Job) de despesas recorrentes (o admin terá que lançar mensalmente).
