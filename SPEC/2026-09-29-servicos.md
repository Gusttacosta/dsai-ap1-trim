# Módulo de Serviços (2026-09-29)

## O quê e por quê

O módulo de serviços define o catálogo daquilo que a barbearia vende: Cortes, Barba, Sobrancelha, etc.
Ele é o coração do fluxo de vendas. Precisamos saber o nome do serviço, quanto custa, quanto tempo demora (essencial para a agenda) e quem está habilitado a realizá-lo.

### Decisões técnicas
- O tempo de duração será medido em minutos inteiros (`duration_minutes`).
- O relacionamento entre Barbeiros e Serviços é **N para N** (Muitos para Muitos), pois um serviço pode ser feito por vários barbeiros e um barbeiro faz vários serviços. Isso requer uma tabela associativa.

---

## Entidades

### Service (Catálogo de Serviços)
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| name | string | unique, not null, max 100 chars |
| description | text | nullable |
| price | decimal | not null, maior ou igual a 0.00 |
| duration_minutes | integer | not null, maior que 0 (ex: 30, 45, 60) |
| is_active | boolean | default true (desativar em vez de deletar para manter histórico) |
| created_at | datetime | auto-gerado |
| updated_at | datetime | auto-atualizado |

### BarberService (Tabela Associativa N:N)
Esta tabela conecta um barbeiro a um serviço que ele sabe executar.
| Campo | Tipo | Restrições |
|-------|------|------------|
| barber_id | UUID | PK composta, FK (barbers.id) |
| service_id | UUID | PK composta, FK (services.id) |
| created_at | datetime | auto-gerado |

## Endpoints da API

### Públicos (sem autenticação)
| Método | Rota | Descrição |
|--------|------|-----------|
| GET | `/api/services` | Lista todos os serviços ativos no catálogo |
| GET | `/api/services/{id}` | Retorna detalhes de um serviço específico |
| GET | `/api/services/{id}/barbers` | Lista quais barbeiros realizam este serviço |
| GET | `/api/barbers/{id}/services` | Lista todos os serviços que um barbeiro específico realiza |

### Autenticados (Admin)
| Método | Rota | Descrição |
|--------|------|-----------|
| POST | `/api/services` | Cria um novo serviço |
| PUT | `/api/services/{id}` | Atualiza nome, preço ou duração de um serviço |
| DELETE| `/api/services/{id}` | Desativa um serviço (soft delete) |
| POST | `/api/barbers/{id}/services` | Vincula um serviço a um barbeiro |
| DELETE| `/api/barbers/{barber_id}/services/{service_id}` | Desvincula um serviço de um barbeiro |

---

## Regras de negócio

1. **Soft Delete:** Se um serviço for "deletado", ele apenas recebe `is_active = False`. Isso é crítico porque agendamentos antigos dependem do ID e do preço histórico do serviço.
2. **Duração em blocos:** A duração do serviço deve ditar o tamanho do slot ocupado na agenda do barbeiro (tratado futuramente no módulo de agendamento).
3. **Listagem bidirecional:** A API deve permitir tanto buscar "quais barbeiros fazem o Corte Degradê" quanto "quais cortes o Barbeiro João faz".
4. **Vínculo único:** A tabela associativa não pode ter registros duplicados (o mesmo barbeiro vinculado ao mesmo serviço duas vezes). As Primary Keys compostas garantem isso.

---

## Critérios de aceitação

- [ ] CRUD básico de Serviços restrito a administradores.
- [ ] Listagem de serviços para clientes deve omitir serviços inativos.
- [ ] Admin consegue associar e desassociar um serviço a um barbeiro.
- [ ] Tentativa de vincular um serviço a um barbeiro que já possui aquele vínculo deve ser ignorada amigavelmente ou retornar um aviso amigável.
- [ ] Ao pedir os detalhes de um serviço, a API deve ser capaz de retornar os barbeiros habilitados para ele.
- [ ] Ao pedir os detalhes de um barbeiro (endpoint estendido do módulo anterior), a API deve ser capaz de listar seus serviços habilitados.

---

## Fora do escopo

- Preço dinâmico por barbeiro (ex: o Barbeiro Júnior cobra R$ 30 pelo corte, o Barbeiro Master cobra R$ 50). Nesta versão, o preço do serviço é tabelado e igual para todos.
- Combos promocionais de serviços (ex: Corte + Barba com desconto). Ficará para o módulo de Produtos/Vendas futuro ou regras de negócio específicas.
