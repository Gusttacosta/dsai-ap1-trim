# Módulo de Galeria e Portfólio (2026-09-29)

## O quê e por quê

A barbearia é um negócio altamente visual. Clientes escolhem onde cortar o cabelo com base em fotos de trabalhos anteriores.
Este módulo permite que os barbeiros subam fotos dos seus cortes e façam uma "vitrine" (portfólio). 
Essas fotos são exibidas publicamente na Landing Page e na página de perfil do barbeiro durante o fluxo de agendamento.

### Decisões técnicas
- O sistema de arquivos (storage) não será implementado fisicamente no nosso banco. A API vai receber e armazenar uma **URL da imagem** (ex: Cloudinary, S3, ou link público genérico) que será fornecida pelo Frontend.
- As fotos possuem estado de aprovação (`is_approved`). Um barbeiro sobe a foto, e ela só fica pública quando um Admin aprovar (evita fotos inapropriadas ou mal tiradas manchando a marca da barbearia).
- Cada foto pode ser opcionalmente associada ao Serviço executado (ex: "Corte Degradê") e a "Tags" visuais.

## Entidades

### GalleryTag (Tags visuais para filtro)
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| name | string | unique, not null (ex: "Fade", "Afro", "Navalhado") |
| created_at | datetime | auto-gerado |

### PortfolioImage (A foto em si)
| Campo | Tipo | Restrições |
|-------|------|------------|
| id | UUID | PK, auto-gerado |
| image_url | string | not null (A URL pública da imagem) |
| barber_id | UUID | FK (barbers.id), not null (Quem cortou) |
| service_id | UUID | FK (services.id), nullable (Qual foi o serviço) |
| description | string | nullable |
| is_approved | boolean | default false (True = visível publicamente) |
| created_at | datetime | auto-gerado |

*(Nota: Faremos uma tabela de associação N:N `portfolio_image_tags` entre PortfolioImage e GalleryTag)*

## Endpoints da API

### Públicos
| Método | Rota | Descrição |
|--------|------|-----------|
| GET | `/api/gallery` | Retorna todas as fotos aprovadas (`is_approved = True`). Permite filtrar por `barber_id`, `service_id` ou `tag_id`. |
| GET | `/api/gallery/tags` | Lista todas as tags disponíveis. |

### Autenticados (Barbeiro / Admin)
| Método | Rota | Descrição |
|--------|------|-----------|
| POST | `/api/gallery` | Barbeiro ou Admin cadastra uma nova URL de imagem, associando ao `barber_id` e tags. (Se for barbeiro, `is_approved` = false por padrão. Se for Admin, true). |
| GET | `/api/gallery/pending` | (Admin) Lista fotos aguardando aprovação. |
| PUT | `/api/gallery/{id}/approve` | (Admin) Muda `is_approved` para True. |
| DELETE| `/api/gallery/{id}` | Deleta fisicamente a referência da imagem (qualquer um apaga a sua própria, Admin apaga qualquer uma). |

---

## Regras de negócio

1. **Moderação (Approval Flow):** Todo barbeiro pode enriquecer seu portfólio. Porém, para manter a qualidade, a barbearia só mostra a foto na landing page (`/api/gallery`) após o dono dar o "check" (`is_approved = True`). O dono (Admin) pode postar direto como aprovado.
2. **Separação de Storage:** O nosso backend não recebe o arquivo `.png`/`.jpg` em base64. O contrato da API prevê receber uma string de URL. A responsabilidade do upload binário é do client (que fará upload pra um Cloudinary, por exemplo, e nos enviará a string do link final).

---

## Critérios de aceitação

- [ ] Barbeiro envia a URL da foto e ela cai na fila de pendentes.
- [ ] Admin aprova a foto e ela passa a aparecer no endpoint de listagem pública.
- [ ] O endpoint público suporta busca flexível (ex: Quero ver todas as fotos com a tag "Fade").
- [ ] Remoção da foto validando autorização (O Barbeiro X não pode apagar a foto do Barbeiro Y, mas o Admin pode apagar qualquer uma).

---

## Fora do escopo

- Upload físico de arquivos (Multipart/Form-Data) para o servidor da FastAPI.
- Crop (recorte) ou filtros de imagem.
- Associação da foto diretamente ao cliente final (evitando problemas de consentimento/LGPD no MVP).
